# 임시 사용자 연결

일정 상세에서 임시 사용자를 가입 완료 사용자에게 연결합니다. 가입 과정에서 이름만으로 자동 연결하지 않습니다.

## 적용 순서

개발/운영이 동일한 DB를 사용하므로 이 SQL을 개발용 DB에 먼저 실행한다는 전제는 없습니다. 운영자가 DB 백업 후 `01-schema.sql`을 **한 번** 실행합니다. 이번 작업에서 공용 DB에는 실행하지 않았습니다.

1. 기존 `20261006-temporary-users`의 통합 사용자 스키마가 적용되어 있는지 확인합니다. 디브리핑 대상 FK 등 이전 마이그레이션의 남은 단계는 해당 README를 따릅니다.
2. `01-schema.sql`을 실행합니다. 사용자 연결 상태 컬럼 2개와 이력 테이블 2개만 추가하며 기존 데이터를 이관하거나 삭제하지 않습니다.
3. `prisma generate --schema prisma/allblue.prisma` 후 백엔드를 빌드/배포합니다.
4. 그다음 앱 변경을 반영합니다. 이전 백엔드에는 새 연결 API가 없습니다. 새 백엔드는 새 컬럼을 조회하므로 SQL을 먼저 적용해야 합니다.

MySQL DDL은 자동 커밋되며 이 스크립트는 재실행용이 아닙니다. 중간 실패 시 추가된 컬럼/테이블을 확인하고 빠진 구문만 적용합니다. 앱/서버 롤백 시 추가 스키마와 이미 생성된 이력은 유지합니다. 구버전 서버는 연결 완료 임시 계정의 재사용을 막지 못하므로 실제 연결 이력이 생긴 후에는 구버전 서버로 단순 롤백하지 않습니다.

## 동작과 권한

- 일정 작성자이면서 해당 임시 사용자를 등록한 사람만 연결할 수 있습니다. 다른 사람의 일정이 섞인 임시 사용자는 자동 연결을 거절합니다.
- 대상은 가입 완료된 일반 사용자입니다. 자기 자신, 다른 임시 사용자, 공용 데모 계정, 서로 차단한 계정은 연결할 수 없습니다. 공용 데모 계정은 연결을 실행할 수도 없습니다.
- 이름/닉네임으로 대상을 검색하고 프로필과 전화번호 끝자리를 확인할 수 있습니다. 확인 화면에서 모든 일정과 기록 수를 표시하고, 명시적으로 확인해야 실행됩니다.
- 현재 일정뿐 아니라 해당 임시 사용자의 전체 일정 참가, 교육 과정/진도, 디브리핑, 서류 소유 관계, 친구/그룹/버디/차단 관계를 이동합니다. 가입 사용자의 로그인 정보, 이름, 프로필, 푸시 토큰은 변경하지 않습니다.
- 확인 정보는 10분간 유효합니다. 대상·범위·원본 기록이 바뀌면 재확인을 요구합니다. 실행자의 ID는 요청 본문이 아니라 인증 토큰에서 얻습니다.
- 같은 원본을 두 번 연결할 수 없습니다. 동일 요청 재전송은 같은 이력 ID를 반환하며 다른 대상으로 재연결할 수 없습니다. 서로 다른 임시 사용자 여러 명을 동일 가입 사용자에게 연결하는 것은 가능합니다.
- 연결한 임시 계정은 삭제 대신 연결 대상/시각을 표시해 남깁니다. 검색에서는 숨기고 신규 참가/교육 진도/디브리핑/친구 등록 등에 재사용하지 못하게 합니다. 로그인 불가 상태도 유지합니다.
- 임시 사용자에 기록을 추가하는 경로와 연결 경로가 동일한 사용자 행 잠금을 사용합니다. 연결 및 이력 저장은 하나의 트랜잭션이며 실패하면 전체 롤백됩니다. 충돌 시 재확인을 안내합니다.

## 중복 처리

| 데이터 | 처리 |
|---|---|
| 동일 일정 참가 | 가입 사용자의 기존 행·분류·참가 상태 유지. 거절/제거 상태도 자동 수락으로 바꾸지 않음 |
| 자격증 과정 | 동일 자격증·강사이며 증서 번호가 호환되는 경우 통합. 완료 우선, 가장 이른 시작일 유지 |
| 다른 강사/다른 증서 번호 | 별도 과정으로 보존 |
| 일정별 과정 연결 | 최종 참가 ID/과정 ID 기준 중복 제거 후 갱신 |
| 교육 진도 | 완료 상태 우선. 이미 완료된 가입 사용자 기록은 평가자/완료 시각까지 유지 |
| 디브리핑 | 작성자·본문·기록 ID 유지, 대상만 이동. 내용이 비슷해도 삭제하지 않음 |
| 서류 | UUID·서명·작성 당시 이름·내용 보존, 사용자 관계만 이동. 일정 없는 서류도 포함 |
| 친구/그룹/버디 | 고유 조합 기준 통합. 버디는 최근 일정 유지. 친구 메모는 200자 이내면 합치고 초과하면 대상 메모 유지, 원본은 감사 이력에 보관 |

연결 자체로 새 초대나 푸시 알림을 만들지는 않습니다. 이후 일반 가입 사용자로서 기존 알림 기능을 사용합니다.

## 이력 및 오연결 정정

`temporary_user_link_audit`에 실행자·임시 사용자·가입 사용자 각각의 숫자 ID/로그인 식별자/당시 표시 이름, 시작 일정, 시각, 행별 변경 전후 값을 저장합니다. `temporary_user_link_schedule`에서 영향받은 모든 일정으로 이력을 찾습니다. 사용자/일정 삭제가 이력을 연쇄 삭제하지 않도록 해당 FK는 만들지 않습니다. 서류 본문·서명과 디브리핑 본문은 감사 이력에 복제하지 않습니다.

이력 API는 연결자와 연결받은 가입 사용자만 조회할 수 있습니다. 복구용 전체 스냅샷을 그대로 반환하지 않으며 친구 메모, 초대 토큰, 서류 UUID, 다른 사람의 비공개 친구/차단 관계는 제외합니다. 원본 감사 테이블은 운영자만 접근해야 합니다.

**앱의 자동 연결 취소 기능은 포함하지 않습니다.** 연결 후 대상 사용자가 추가한 기록까지 잘못 되돌리지 않도록 운영자가 아래 절차로 정정합니다.

1. 이력 ID, 잘못 연결된 대상, 실제 대상, 요청자와 확인 근거를 확보합니다.
2. 해당 사용자들의 기록 쓰기를 중지하고 DB 백업을 확보합니다. `details.changes`와 현재 행을 비교해 연결 이후 변경된 항목을 구분합니다.
3. `sourceBefore/sourceAfter` 및 행별 `before/after`를 기준으로 정정할 행만 선정합니다. 삭제된 중복 행은 FK 부모부터 복구하고 자식 관계를 복구합니다. 기존 대상 행에 합쳐진 진도·메모 등은 현재 값이 당시 `after`와 같을 때만 원복 후보로 삼습니다.
4. 연결 후 새로 작성된 기록이나 수정 사항은 자동 이동/원복하지 않고 별도 판단합니다. 서류의 서명·원문은 수정하지 않습니다.
5. 검토한 정정 SQL을 트랜잭션으로 실행합니다. 최초 감사 이력은 삭제/수정하지 말고 정정 담당자·시각·사유·대상 행과 SQL을 별도 운영 기록에 보관합니다. 기존 연결 상태만 초기화해서 다시 연결하는 방식은 사용하지 않습니다.
6. 관련 일정·로그·서류·진도를 확인하고 쓰기를 재개합니다.

## 검증

- 앱: `npm test`, `npm run typecheck`. 연결 확인 필수, 연속 탭 차단, 충돌 후 재확인, 닫힌 팝업의 지연 응답 무시를 포함합니다.
- 백엔드: AllBlue Jest 테스트 및 TypeScript 컴파일. 이관 계획, 중복 과정 키 충돌, 접근 권한, 감사 조회 필드 제한 등을 포함합니다.
- `test/temporary-user-link.integration.cjs`: 공용 DB URL을 읽지 않습니다. `ALLBLUE_LINK_TEST_DATABASE_URL`로 지정한 `127.0.0.1`의 `_link_test`로 끝나는 격리 DB만 허용합니다. 별도로 스키마를 구성하고 `link-test-dist`로 컴파일한 후 실행합니다. 테스트는 고유 접두사 픽스처를 추가하고 DB를 자동 삭제하지 않습니다.

실제 기기에서는 다음을 확인합니다.

1. 등록자가 임시 사용자가 포함된 일정 상세를 열면 연결 버튼이 보이고, 다른 참석자에게는 보이지 않는지 확인합니다.
2. 동명이인 프로필을 확인하고 대상 선택 → 전체 기록 확인 → 확인 체크 → 연결을 진행합니다. 짧은 화면에서도 키보드가 올라온 상태에서 검색 결과를 스크롤할 수 있어야 합니다. 팝업은 공통 어두운 블러 배경을 사용합니다.
3. 연결받은 계정으로 로그인해 옮겨진 일정, 디브리핑, 다이빙로그, 진도와 서류를 확인합니다. 기존 서명/작성 당시 이름은 그대로여야 합니다.
4. 중복 일정의 기존 참가 상태와 분류, 중복 교육 진도의 완료 표시가 유지되는지 확인합니다.
5. 모든 영향 일정에서 연결 이력의 실행자·시각·대상·변경 내역을 확인합니다. 무관한 계정은 해당 이력을 볼 수 없어야 합니다.
6. 연결 전에 열어 둔 다른 기기에서 임시 사용자로 기록을 추가하면 새로고침 안내가 나오는지 확인합니다.
