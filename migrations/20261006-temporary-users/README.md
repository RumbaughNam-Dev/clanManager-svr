# 임시 사용자 통합 — 기존 guest 삭제

개발·운영은 **동일 DB**를 사용합니다. 사용자가 01-expand.sql 실행을 완료했습니다. 재실행하지 않습니다. 기존 guest_user는 이관하지 않고 삭제한다는 요청을 반영했습니다. 종전 이관용 SQL은 제거했습니다.

## 적용 순서

1. 현재 변경된 백엔드를 별도 디렉터리에서 빌드해 배포 준비를 합니다.
2. 공용 DB를 사용하는 개발·운영 서버와 쓰기 작업을 모두 중지합니다.
3. `02-drop-legacy-guests.sql`을 한 번 실행합니다. 기존 guest_user, 참가자 guest_id, 서류 participant_guest_id를 제거합니다. 외래키 이름은 실제 DB에서 조회해 제거합니다. DELIMITER를 지원하는 MySQL 클라이언트를 사용하고 오류를 무시하지 않습니다.
4. `03-verify.sql`의 결과가 모두 0인지 확인하고 `04-debriefing-constraint.sql`을 한 번 실행합니다.
5. **새 Prisma 클라이언트를 포함한 새 백엔드**를 개발·운영 양쪽에 반영한 뒤 재시작합니다. 기존 서버는 삭제된 컬럼을 조회하므로 SQL만 먼저 실행한 상태에서 가동하면 안 됩니다.
6. 새 앱을 배포하고 임시 사용자 등록·검색·일정 수정·디브리핑·로그를 확인합니다.

현재 공유 DB에 삭제 SQL을 실행하거나 서버를 배포하지는 않았습니다. SQL 실행은 사용자가 하기로 한 범위를 유지합니다. MySQL DDL은 암묵적으로 커밋하므로 실행 중 오류가 나면 나머지를 계속 실행하지 않고 실패 지점부터 확인합니다.

## 삭제 범위와 보존 범위

- 기존 guest_user의 데이터와 테이블을 삭제합니다. 일반 user와 새 임시 user는 삭제하지 않습니다.
- guest 전용 일정 참가자 행 및 그 행에 종속된 자격증 연결을 제거합니다. 실제 user가 연결된 참가자 행과 일정 자체는 유지합니다.
- 실제 user가 없고 해당 일정 guest로만 식별되는 디브리핑을 제거합니다. 일반 사용자 디브리핑은 유지합니다. 식별할 수 없는 나머지 기록이 있으면 데이터 변경을 롤백하고 중단합니다.
- 기존 서류는 UUID·서명·이름·내용을 보존하고 guest 연결만 제거합니다. 등록 강사의 서류 목록에서 조회할 수 있습니다.
- 새 데이터는 user.is_temporary와 temporary_owner_id로 구분합니다. 기존 guest 테이블 조회/정리 코드는 제거했습니다. 예전 앱의 isGuest 응답 필드는 false로 유지합니다.

임시 사용자는 이름만으로 등록하며, 등록자만 검색·프로필·자격증·친구 추가를 할 수 있습니다. 디브리핑·진도·로그는 일반 사용자와 같은 권한/교육 이력 조건을 사용합니다. 임시 사용자의 로그인·초대 수락·푸시 수신은 지원하지 않습니다.

## 이번 정리 검증

Prisma 생성, 서버 TypeScript 검사, 커밋 대상 코드의 AllBlue 테스트 78개가 통과했습니다. 별도 로컬 MariaDB에서 삭제 SQL을 실행해 기존 guest 테이블/컬럼 제거, 일반·신규 임시 사용자 보존, 서명 문서 보존, 미확인 기록 발견 시 DDL 전에 롤백되는 동작과 디브리핑 외래키 추가를 확인했습니다. 공유 DB에서는 실행하지 않았습니다.
